# JOBIN Telegram-бот

Реалізація ТЗ: асинхронний бот на **Python (Aiogram 3.x)** + **SQLite** (SQLAlchemy async) +
**APScheduler** для нагадувань про покинутий кошик.

## Структура проєкту

```
jobin_bot/
├── main.py                 # точка входу
├── config.py                # завантаження .env
├── callbacks.py              # callback_data фабрики
├── states.py                 # FSM-стани
├── scheduler.py               # нагадування про покинутий кошик (2 год)
├── texts.py                   # ТЕКСТИ акції, доповнень і підсумку — можна редагувати
├── utils.py
├── database/
│   ├── models.py             # ORM-моделі (User, Category, Product, Order, CartView)
│   ├── crud.py                # функції роботи з БД
│   └── seed.py                 # первинне наповнення каталогу з ТЗ
├── keyboards/
│   ├── user_kb.py              # клавіатури клієнта
│   └── admin_kb.py              # клавіатури адміна
└── handlers/
    ├── user.py                 # /start, каталог, квитанція, історія, менеджер
    ├── checkout.py             # акція 1+1=3, додаткові опції, підсумок і реквізити
    ├── admin.py                  # модерація замовлень, /admin
    ├── admin_catalog.py           # CRUD каталогу (без правок коду)
    └── admin_crm.py                # розсилка + експорт бази у .xlsx
```

## Запуск

1. Встановіть залежності:
   ```bash
   pip install -r requirements.txt
   ```
2. Скопіюйте `.env.example` у `.env` та заповніть:
   - `BOT_TOKEN` — токен від @BotFather
   - `ADMIN_IDS` — ваш Telegram ID (і колег), через кому
   - `PAYMENT_CARD` / `PAYMENT_IBAN` — реквізити для оплати
   - `MANAGER_USERNAME` — юзернейм для кнопки "Зв'язок з менеджером"
3. Запустіть бота:
   ```bash
   python main.py
   ```

При першому запуску база `jobin.db` створюється автоматично, а каталог наповнюється
актуальним прайсом: пакети START / BUSINESS / PRO / MAX, окремі розміщення та додаткові
опції (Circle, Video Vacancy, Закріплення). Підписок немає.

## Акція «1+1=3» і додаткові опції

Після кнопки «Купити» клієнт проходить крок за кроком (кожен крок можна пропустити):
1. Якщо обрано окреме розміщення — пропозиція акції: ще одне платне + одне в подарунок.
   Подарунок не може бути дорожчим за будь-яке з двох платних розміщень.
   Розсилка в акції не бере участі.
2. Додаткові опції (Circle, Video Vacancy, Закріплення). У пакетах із безкоштовним
   закріпленням (BUSINESS, MAX) окремо «Закріплення» не пропонується.
3. Підсумок із сумою та реквізитами (картка, IBAN, за потреби USDT TRC-20).

Тексти змінюються у файлі `texts.py`. Акцію для конкретної послуги вмикають/вимикають
в `/admin` → Каталог → послуга → «Акція 1+1=3».

## Правка цін і посилань

Ціни, описи та посилання змінюються після запуску через:

`/admin` → `🗂 Каталог послуг` → категорія → послуга → ✏️ потрібне поле.

Так само можна додавати нові послуги (`➕ Додати послугу`), вимикати без видалення
(🟢/🔴) або видаляти назавжди — все без правок коду, як і вимагає п. 3.2 ТЗ.

## Реалізовані сценарії з ТЗ

- **2.1–2.3**: `/start`, каталог із трьох категорій, картка товару з описом/ціною/
  бонусом/посиланнями, кнопка «Купити» → повідомлення з реквізитами → очікування
  фото/документа квитанції → сповіщення адміну з кнопками модерації.
- **2.4**: якщо клієнт переглянув товар і за 2 години не надіслав квитанцію —
  автоматичне нагадування (одноразово на перегляд, `scheduler.py`).
- **3.1**: модерація в чаті адміністратора — Підтвердити (запитує в клієнта текст
  вакансії) / Відхилити (запитує причину, надсилає клієнту) / Написати (прямий діалог).
- **3.2**: CRUD каталогу через інлайн-меню.
- **3.3**: розсилка тексту+медіа всім користувачам з захистом від Flood Wait
  (`asyncio.sleep` між надсиланнями + обробка `TelegramRetryAfter`), а також
  експорт бази клієнтів у `.xlsx` (ID, Username, дата приєднання, історія замовлень).

## Не увійшло в цю версію (за потреби — легко додати)

- Перегляд ТЗ згадує MongoDB Atlas / PostgreSQL / Docker як альтернативи — тут
  свідомо обрано SQLite для найпростішого деплою без зовнішніх сервісів
  (легко перейти на PostgreSQL: достатньо змінити рядок підключення в `database/models.py`).
- Постановка бота на Docker/cron-job.org — модуль `scheduler.py` вже ізольований,
  тож для продакшн-навантаження APScheduler можна замінити на Celery без
  переписування бізнес-логіки.

## Оплата в USDT (TRC-20)

Якщо в `.env` вказано `PAYMENT_CRYPTO`, клієнт бачить гаманець і суму в USDT, розраховану
автоматично за офіційним курсом НБУ (USD = USDT), округлену вгору до центів. Курс кешується на 10 хвилин.
- `USDT_RATE` — свій фіксований курс (тоді НБУ не опитується).
- `USDT_MARKUP_PERCENT` — надбавка до курсу НБУ у відсотках.
Якщо курс отримати не вдалося, бот пропонує написати менеджеру. Адміну в сповіщенні
показується сума в USDT «для довідки». Binance з 28.09.2026 не торгує парою USDT/UAH, тому не використовується.
